# Memory V3

## 1. 目标

Memory V3 的目标不是继续把 V2 的结构化索引做得更复杂，而是增加一个**自由工作区**：

- 只存 Markdown 文件
- 不预先规定文件内容
- 不预先规定文件格式
- 不预先规定命名规范

它的定位是：

- 给 agent 一个可自由读写的长期工作区
- 允许 agent 自己决定要存什么
- 允许 agent 自己决定怎么组织这些信息

## 2. 核心原则

V3 工作区只强调三个约束：

1. 工作区是独立目录
2. 目录里只允许 `.md` 文件
3. agent 可以自由查询、修改、创建这些 `.md`

除此以外，V3 不强加：

- 固定 schema
- 固定 frontmatter
- 固定摘要模板
- 固定层级结构
- 固定字段命名

## 3. 与 V1 / V2 的区别

### V1

- 当前局短期记忆
- 面向 prompt 注入
- 结构受控

### V2

- 已结束 run 的结构化归档
- 面向检索、统计、回放
- JSON / SQLite 为主

### V3

- agent 自由工作区
- 面向“自定义长期经验积累”
- 只要求 `.md`

## 4. 当前工作区模型

当前 V3 已经落地到固定目录：

```text
memory/globao_memory/
```

目录中的文件只要求：

- 后缀是 `.md`

当前实现允许：

- 子目录

当前实现不接受：

- 非 `.md` 文件作为正式工作区内容

如果出现非 Markdown 文件，它们会被前端状态标记为 invalid files。

除此之外全部交给 agent 决定，例如：

- 经验总结
- 对局观察
- 特定敌人笔记
- 路线偏好
- 卡牌评价
- 遗物优先级
- 失败复盘
- 某个角色的专题笔记

## 5. 边界

V3 要做：

- 提供可持久化的 Markdown 工作区
- 允许 agent 自由读写
- 不要求固定 schema

V3 不做：

- 在设计阶段预定义 Markdown 模板
- 强制规定文件名规则
- 强制规定目录结构
- 强制规定哪些内容必须写入

## 6. 当前状态

当前 V3 已开始实现，已经包含：

- 工作区目录创建
- `.md` 文件扫描
- invalid file 检查
- 前端状态 / 搜索 / 文件读取 API
- 前端工作区面板
- `sts2-v3-workspace` skill

当前还没有：

- 自动 lessons 抽取
- 自动整理已有 Markdown
- 更高级的 workspace 检索能力
